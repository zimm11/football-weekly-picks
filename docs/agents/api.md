# The API

Paths are under `apps/api/` unless they start from the repo root. Each area's routes and rules are in that area's doc; this one covers the API's shape, the Workers runtime, the schedule provider, and logging.

## Shape

- `src/app.ts` builds the app (`createApp` takes deps, so tests inject fakes) and has the health, config and profile routes. The rest are one module per area (`src/leagues.ts`, `src/weeks.ts`, `src/messages.ts`, `src/moderation.ts`, `src/operator.ts`, `src/push.ts`, `src/unsubscribe.ts`, `src/accounts.ts`) and per league type (`src/playoff.ts`, `src/squares.ts`, `src/survivor.ts`, mounted in `app.ts`).
- `src/context.ts` has the access checks and the shared `param`/`query`/`body` validators. `src/auth.ts` verifies Supabase access tokens (`requireAuth`).
- `src/services.ts` (`createServices`) holds what route modules share per app instance: the provider's weeks behind the results throttle, and `advanceLeagueOnRead`.
- `src/weekOps.ts` holds the week chores every type and automation share (`importSlate`, `openWeek`, `writeFinals`, `fillFinishedGames`, `finalizeWeek`, `markRecapSeen`, `reopenWeek`), each taking a database handle or a transaction.
- `src/jobs.ts` is `runScheduledJobs`, which the Cron Trigger calls.
- `src/env.ts` validates the environment; `src/clock.ts` is the local clock override; `src/devHarness.ts` the local E2E harness.
- `src/index.ts` is the Node entrypoint (local dev, tests); `src/worker.ts` the Cloudflare Worker's (production). `wrangler.jsonc` configures the Worker; `worker-configuration.d.ts` is generated by `pnpm --filter @picks/api cf-typegen` (rerun after changing bindings).
- `packages/db` has `createDb` (Node), `createHyperdriveDb` (one connection per Worker request) and the TLS policy (`packages/db/src/connection.ts`).
- Keep routes chained on the Hono instance, or `ApiType` loses its route types. Request bodies over 64 KB get a 413.

## Runtime (Cloudflare Workers)

Code the API runs must work on Node and in Workers: no native addons, no files read from disk at runtime.

- `src/worker.ts` builds the app once per isolate and opens a Hyperdrive connection per request (and per Cron Trigger run). Routes keep using `deps.db`; a stand-in forwards it to the current request's connection (`AsyncLocalStorage`). **Don't touch the database outside a request.**
- **Hyperdrive's query cache is off; keep it off.** It isn't cleared by writes, so access checks and reads after a save would go stale.
- **Work that outlives the response** (a new thread's emails and notifications) goes through the `background` dep, which the Worker hands to that request's `waitUntil` and finishes before closing its connection. A bare un-awaited promise is cancelled once the response is sent.
- **In-memory caches** (`cached` in `insights.ts`, the results throttle) are per isolate and keep only settled values: a Worker request must not await a promise another request started. Don't share in-flight promises, sockets or streams across requests.
- **CPU:** `limits.cpu_ms` in `wrangler.jsonc` caps each invocation at 2 s (API requests use roughly 10–130 ms), so raise it before adding heavier work, and keep heavy computation out of hot routes.
- **Environment:** the Worker reads `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY`, `OPERATOR_USER_IDS`, `UNSUBSCRIBE_SECRET` and the three `VAPID_*` keys (secrets), `APP_URL`, `MODERATION_MODE` (`enforce` by default; `off` is the emergency switch) and `NODE_ENV`, and optionally `EMAIL_FROM`, `EMAIL_DAILY_LIMIT` and `EMAIL_MONTHLY_LIMIT`. `pnpm worker:dev` sets `NODE_ENV=development`, which drops the TLS requirement for local Postgres and lets `INBOX_URL` send email to the test inbox. `CLOCK_OVERRIDE` is Node-only. `DEV_HARNESS=1` (E2E only) is refused unless `NODE_ENV=development`.

## The schedule provider (ESPN)

- `src/nfl.ts` is the schedule, odds and results provider: ESPN's public scoreboard feed, unofficial and keyless. `src/insights.ts` is the provider behind the matchup sheet (ESPN's game summary and team news, cached in memory).
- The app reads ESPN leniently so it stays up when a feed changes; the contract checks (`pnpm test:contract`, `test/contract/`) are what notice. Run them after changing how ESPN is read, and extend them for any new field the app relies on.
- Postseason: the provider maps weeks 19–21 onto ESPN's postseason weeks 1–3 and finds the Super Bowl's week in the feed's calendar (5 after a Pro Bowl week; the 2026 season lists it as 4). It drops "TBD at TBD" games until both teams are known.
- It reports each game's status, current period and cumulative score per settled quarter (`periodScores`: q1, half, q3, final with overtime).
- Players never read the provider's name; see "Copy" in `docs/agents/design.md`.

## Logging and credentials

- API logs use route templates, generated request IDs, fixed readable messages, known error codes and safe source locations. Never print raw errors, SQL parameters, request bodies or headers, or raw URLs. Extend the safe diagnostic vocabulary in `src/logging.ts` when adding a new operation.
- Remote database connections require verified TLS. `packages/db/src/connection.ts` is the shared policy for the Node API and `scripts/check-db-url.mjs`; the public Supabase CA is bundled and scoped to Supabase database hosts. In production Hyperdrive verifies the database with `--sslmode verify-full` and the same CA. Never disable certificate verification to work around a trust failure.
- CLI wrappers redact credentials before printing. `scripts/supabase-env.mjs` intentionally exports local credentials to `.env` or `GITHUB_ENV`; do not pipe it into public logs.
- `scripts/check-db-url.mjs` checks a connection string without printing the password: `pbpaste | node scripts/check-db-url.mjs`.
