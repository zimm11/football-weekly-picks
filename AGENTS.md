# Football Weekly Picks

The app is called **POW Pick'em** in everything players see, and lives at `www.pow-pickem.com`. "Football Weekly Picks" is the repository and service name only.

An NFL pick'em league: each week players pick every game against the spread, mark one Pick of the Week (POW),
and guess the Monday night total as a tiebreaker. A league's admins set up and close each week. See "Domain rules".

pnpm monorepo: React web app + Hono API (TypeScript) + Supabase (managed Auth + Postgres). Deployed by GitHub
Actions as one Cloudflare Worker: Static Assets serve the client-side SPA from the edge, and `/api/*` runs the
Hono API in the Workers runtime, reaching Postgres through Hyperdrive. One origin, no proxy, no cold starts.
Local development and tests run the same API on Node. Code the API runs must work in both: no native addons,
no files read from disk at runtime, and nothing shared between requests except settled values (see
"Runtime").

## Layout

- `apps/api` — Hono API. `src/app.ts` builds the app (`createApp` takes deps, so tests inject fakes) and has the health, config and profile routes; the rest live in `src/leagues.ts` (leagues, members, invites, standings), `src/weeks.ts` (week setup, games, picks, results, recap, insights), `src/messages.ts` (the message board) and `src/operator.ts` (feedback, and the operator dashboard for `OPERATOR_USER_IDS`); `src/auth.ts` verifies Supabase access tokens (`requireAuth`); `src/context.ts` has the access checks and the shared `param`/`query`/`body` validators; `src/nfl.ts` is the schedule/odds/results provider (ESPN's public scoreboard feed). `src/insights.ts` is the provider behind each game's matchup sheet: team form, injuries and news from ESPN's game summary, and win/cover prices from Kalshi's public market API, cached in memory. Email: `src/email.ts` (mailers: Cloudflare's `send_email` binding in production, the local test inbox in development; signed unsubscribe tokens), `src/templates.ts` (notification emails), `src/outbox.ts` (queueing, sending and retrying through the `email_outbox` table; pick reminders; `runEmailJobs`), `src/reminderTargets.ts` (who is due a pick reminder, and the send-time recheck, shared by email and push), `src/unsubscribe.ts` (one-click `POST /unsubscribe`). Push: `src/push.ts` (device subscription routes), `src/pushQueue.ts` (queueing and sending through `push_deliveries`), `src/pushSender.ts` and `src/webPush.ts` (Web Push on WebCrypto and fetch, no `web-push` package, so the Worker can send). `src/jobs.ts` (`runScheduledJobs`, which the Cron Trigger calls: `runEmailJobs` and `runPushJobs`). `src/env.ts` validates the environment, `src/logging.ts` is the safe logger, `src/clock.ts` the local clock override, `src/index.ts` the Node entrypoint (local dev, tests), and `src/worker.ts` the Cloudflare Worker entrypoint (production). `wrangler.jsonc` configures the Worker; `worker-configuration.d.ts` is generated by `pnpm --filter @picks/api cf-typegen` (rerun after changing bindings).
- `apps/web` — Vite + React. `src/api.ts` has the typed Hono client (`hc<ApiType>`) and the Supabase client. `src/App.tsx` holds the session, the header and account menu, and picks the page for the route. `src/components/` holds presentational components, `src/pages/` the containers that fetch, `src/router.tsx` a small History API router. `src/lib/` holds hooks and pure helpers: `usePolling` (refetch on an interval, paused in hidden tabs), `useAction` (one action at a time, with its name as the busy state, then `notifyDone`/`notifyError`), `unread.ts` (the Messages tab's unread count), `recap.ts`. Styling is Tailwind v4 with shadcn/ui components copied into `src/components/ui/` (see "Design").
- `e2e/` — Playwright end-to-end tests and config.
- `scripts/` — `ports.mjs` (per-worktree ports), `ci-ports.mjs` (a free port group for CI), `supabase.mjs` (CLI wrapper), `supabase-env.mjs` (writes `.env`), `check-db-url.mjs` (checks a connection string without printing the password: `pbpaste | node scripts/check-db-url.mjs`), `icons.mjs` (draws the app icons), `worker-dev.mjs` (`pnpm worker:dev`), `check-live.mjs` (the deploy's live health check, also run every 15 minutes by `uptime.yml`), `vapid-keys.mjs` (a new Web Push key pair), `contract-issue.mjs` (the feed contract alert's issue text). The `*.test.mjs` files beside them run under Node's test runner; `headers.test.mjs` keeps `_headers`' security headers and CSP in place.
- `packages/db` — Drizzle schema (`src/schema.ts`, the **source of truth** for the DB), the `createDb` client (Node) and `createHyperdriveDb` (one connection per Worker request), and the TLS policy (`src/connection.ts`).
- `packages/shared` — Zod schemas and types shared by API, web, and the future mobile app. `src/rules.ts` is the rules engine (point values, locks, scoring, tiebreakers) as pure functions; change league rules there. `src/awards.ts` derives the weekly awards, `src/stats.ts` the season and week analytics shown on Standings and Results, and `src/seasons.ts` holds season defaults, guided week suggestions, display phases, and actionable pick counts. `src/reminders.ts` decides when a pick reminder is due. `src/time.ts` has the time-zone helpers (`canonicalTimeZone`), `src/teams.ts` the NFL teams and logos, and `src/insights.ts`, `src/push.ts`, `src/messages.ts` and `src/operator.ts` the schemas for those features. `src/index.ts` also holds the league size limits.
- `supabase/` — Supabase CLI config, generated SQL migrations, Auth email templates (`templates/`), and `seed.sql` (local only: four test accounts, a league, and four closed weeks; the README lists the logins). Update the seed when a schema change would break it.

## Domain rules

- **Structure:** league → seasons (by year) → weeks (1–18, regular season only) → games → picks. A league keeps its members across seasons. Whoever creates a league is its first admin; others join through its invite link (`/join/<code>`), which an admin can replace so old links stop working.
- **Admins:** a league can have several, all equal. Any admin can make a member an admin, revoke another admin (or themselves), and remove members, including the creator. A league always keeps at least one admin. "The admin" below means any of them.
- **Limits:** at most 100 active members in a league and 25 active leagues per player (`MAX_LEAGUE_MEMBERS`, `MAX_LEAGUES_PER_USER` in `packages/shared`). Creates and joins check them under a lock; rejoining a league you are already in counts against neither.
- **Home-screen help:** browser users find it in Settings (the **Home screen app** card, **Show me how**; left out in an iPhone tab, where the notifications card shows the steps); it opens a bottom sheet with the steps for their platform (iOS or Android; both elsewhere) without leaving the page. On a phone, the first successful pick save in a browser opens the same sheet once, with **Not now** (`pow:home-screen-offered` in localStorage; no storage means no offer). Computers never get the automatic offer. Hide all of it in standalone mode (including iOS). The logic is in `components/HomeScreenInstall.tsx` and `lib/homeScreen.ts`.
- **Accounts:** email and password through Supabase Auth, then a display name (required before anything else; the API refuses to create or join a league, or post, without one). "Forgot password?" emails a link that signs the player in on `/reset-password`; the account menu reaches the same screen as "Change password". `/`, `/login` and `/how-to-play` work signed out.
- **Week lifecycle:** `draft` (admin only: import games and spreads from the provider, then add/remove games, edit spreads and point values; a kickoff typed in by hand is in the league's time zone, and a game whose kickoff moves, by re-import or edit, takes the new slot's default points unless the admin had set them by hand) → `open` (players pick; spreads are fixed unless the admin edits them) → `final` (scored; everyone's picks revealed). Results arrive three ways: automatically (below), the admin's "Pull results" (which replaces typed scores), or typed in by hand. Then the admin closes the week; a closed week can be reopened to correct it.
- **Live results:** `GET /weeks/:id` on an open week fills in the provider's final scores for games that came from it, have been under way at least 2.5 hours, and have no result. It never overwrites a score already entered and never touches spreads. The provider is asked at most once a minute per season week (`RESULTS_REFRESH_MS` in `apps/api/src/weeks.ts`), shared across leagues, and a failure is remembered for the same minute. It runs on read, not on a timer, so nothing runs while nobody is looking. While a game has kicked off without a result, the pick sheet refetches the week every minute and when the tab becomes visible again. It marks each settled pick Won (with points), Lost or Push, and `WeekSoFar` totals the player's own points, record and POW (`scoreSoFar` in `rules.ts`). That is the player's own data only, so the privacy rule holds.
- **Picks are private until the week is final.** No endpoint returns another player's picks, points or standings contribution for a week that isn't `final`.
- **Points:** Thursday and Monday 3; Sunday night, Tuesday, Wednesday, Friday, Saturday 2; other Sunday games 1; Thanksgiving and Christmas Day 4. A winning POW adds 5. A push scores nothing and is neither a win nor a loss. Spreads are stored as the home team's line.
- **Locks:** each game locks at its kickoff. Until then its pick can be added or changed, and the POW can be put on it, moved off it, or removed. Once the game holding a player's POW has kicked off, the POW can't be moved or removed. A game with a result entered is locked whatever the clock says. The tiebreaker guess can be entered or changed until the tiebreaker game locks. There is no automatic POW: a player who doesn't choose one has none that week. On the pick sheet, an unsaved change on a game that locks (or was removed) is undone before saving, and the save bar says which change didn't make it. The league's time zone (stored as a canonical IANA Area/City name, or UTC) only decides how game days and times are shown. The tiebreaker game is the admin's explicit choice if they made one, otherwise the last Monday game (else the last game), worked out from the slate on every read.
- **Screens:** inside a league, five tabs (a bar along the bottom on phones, a row under the league name on wider screens): `/leagues/:id` is **Picks** (the pick sheet for the current open week: prioritize missing picks that can still be submitted, then editable picks, then any available games, else the latest open week; keep the displayed sheet stable during background refreshes), `/leagues/:id/results` lists closed weeks, `/leagues/:id/standings` is the season table, `/leagues/:id/messages` is the league-wide message board (threads, replies, and per-player unread indicators), and `/leagues/:id/league` has members and the admin's tools (set up a week, invite link, settings). `/weeks/:id` is one week as every player sees it: the pick sheet while open, results once final; saving picks stays on the sheet. `/weeks/:id/manage` is admin-only week management (games, spreads, results, open/close); after opening or finalizing a week it offers to post a message-board thread announcing it. Keep picking and managing on separate screens. Outside leagues: `/join/<code>` joins through an invite, `/feedback` sends feedback (at most `FEEDBACK_DAILY_LIMIT`, 5, a day), `/operator` is the operator dashboard (feedback inbox and app-wide counts; a 404 for anyone not in `OPERATOR_USER_IDS`), `/account` is **Settings** (notifications by email and on this device, the home-screen app, email address, and a link to change password; `/notifications` shows it too, for old links), `/reset-password` is where a password-reset email lands and where the account menu's **Change password** goes, and `/unsubscribe?token=` asks before turning an email off and works signed out (mail scanners open links, so nothing changes on a GET).
- **Announcements and quotes:** only league admins can pin, unpin or permanently delete threads. Deletion uses the thread’s ⋯ menu and a confirmation, removes all replies, reactions, read markers and queued notifications, then returns to the message board. Pinned announcements appear first on the board without changing unread status. The board loads 30 threads at a time (pinned ones always on the first page) with **Load older threads**. Members can quote any message in the same thread when replying; the composer previews the quote and lets them remove it without losing their draft. Posted quotes attribute the original author and link back to the original message.
- **Message reactions:** active members can add or remove 👍, 😂, 🔥, 🎉, 😮, 🙏 and 🏈 on any message or reply, once per emoji per player. A message shows only the emoji someone has used, with counts and your own selections; the smiley button ("Add reaction") opens the full set. Reactions do not bump threads or mark them unread.
- **Season and week UI:** one season selector applies across the season-based league tabs and is remembered per league in browser session storage. New seasons are staged explicitly and created with their first week. Future drafts do not displace the default published season. The admin chooses from weeks 1–18 with existing states shown; existing weeks open management instead of creating duplicates. Display phases are derived from kickoffs and scores (Draft → Accepting picks → Games underway → Awaiting finalization → Final); the database still stores only draft/open/final. Only an admin finalizes a week, using **Finalize week**.
- **Membership and history:** removing a player, or a player leaving (League tab → Leave league; the only admin can't until someone else is one), marks the membership (`removed_at`) instead of deleting it. They lose access and can rejoin through an invite link. Each closed week is scored for the people who were in the league when it was played: a player removed after the week's last kickoff stays in it, and one who joined after it isn't added. Finalizing records that list in `week_participants` (everyone in the league at the last kickoff, plus anyone who picked); leaving or rejoining later never changes it, and finalizing again after a reopen only adds players. Weeks finalized before the table existed have no rows and are worked out from membership dates. Don't score past weeks from the current member list.
- **Pick submissions** run in one transaction that locks the week row and takes a per-player advisory lock, so the lock rules can't be raced. Keep reads, validation and writes inside it.
- **Weekly winner:** most points, then most games won, then closest guess at the tiebreaker game's total (on equal distance, the guess that didn't go over).
- **Season standings:** total points, then POWs won, wins, Monday night wins, Sunday night wins.
- **Awards and the Low Point Loser (LPL):** `packages/shared/src/awards.ts` works them out from a final week's results. The LPL is last place by the weekly ranking (shared if still level; nobody when the whole league is level). The others are perfect week, bullseye (exact tiebreaker total) and lone wolf (alone on the covering side of a game at least three players picked).
- **Email:** Supabase Auth sends sign-in emails (password reset, email change, change notices) through Cloudflare Email Sending's SMTP relay. The Worker sends notification emails through its `send_email` binding: a new message thread (to the league's other current members) and a pick reminder (7pm league time the evening before a game day, to members with games still to pick that day; it expires at the day's first kickoff). Notification emails are queued in `email_outbox` with a dedupe key and sent after the request commits, never inside it; addresses are read from `auth.users` at send time and never copied. Just before sending, a thread email is skipped if the recipient has left the league, and a reminder is skipped if it no longer applies (left, week not open, everything picked) or re-rendered with only the games still unpicked. Each kind can be turned off per player (`profiles.email_*`), and every email carries a signed unsubscribe link. Every send first reserves a slot in `email_usage` against `EMAIL_DAILY_LIMIT` / `EMAIL_MONTHLY_LIMIT` (a safety cap against runaway sending, defaults 1,000 a day and 10,000 a month); over budget, emails wait for the next UTC day. Don't add a send path that skips the outbox. The Worker's Cron Trigger runs `runScheduledJobs` (email and push) every five minutes (`pnpm dev` uses a one-minute timer); the job must stay idempotent. In each job a failure to queue (caught per week) never stops sending what's waiting. Email is off until `UNSUBSCRIBE_SECRET` is set.
- **Push notifications:** opt-in per device in Settings → **On this device** (`push_subscriptions`). Your leagues suggests it once per browser (`NotificationsPrompt`: only while the browser hasn't asked for permission, or in an iPhone tab; **Not now** sets `pow:notifications-prompt-dismissed`). Keep it a suggestion, not a permanent row. New threads notify other current members who opted in; missing-pick reminders use the same 7pm rule as email (`dueReminderDay`) and expire at the day's first kickoff. Deliveries are queued in `push_deliveries` (inside the thread's transaction for new threads), and membership, preferences, week state and missing picks are rechecked just before sending. Payloads carry league names and thread titles, never picks or message bodies. Signing out disconnects the device. When a browser replaces its subscription, the service worker reports the change and the app re-registers it for the same player (`oldEndpoint` on `PUT /push/device`). A device is removed only when its push service says the subscription is gone (404/410); other failures are logged by a fixed code and never remove it, since a 401/403 or an outage may be our side's fault. Push is off until the three `VAPID_*` secrets are set, and stays off if they don't form a matching pair.
- **Results recap:** the first time a player opens a league after a week is finalized, a bottom sheet (`WeekRecap`) shows how they finished and the awards, once. `weeks.finalized_at` is set on finalize and cleared on reopen; `week_recap_views` records who has seen it, and a view older than `finalized_at` doesn't count, so a corrected week is recapped again. The league endpoint's `recapWeekId` names the latest such week closed since the player joined. The admin who finalizes is marked as having seen it. Weeks closed before the feature have no `finalized_at` and never get one.

## Design

- **One theme, dark only.** Tokens live in `apps/web/src/styles.css`: navy surfaces, electric blue (`primary`) for the player's pick and the main action, red (`pow`) for the Pick of the Week and nothing else, green (`win`) for won picks and results, coral (`destructive`) for lost picks, errors and removals, `--avatar-*` for player avatars. Use the tokens; don't hard-code colors.
- **Surfaces, not outlines.** Layers are told apart by fill: `background` → `card` → `raised` (selected rows, unpicked buttons, hover). Borders are hairlines for dividers, not boxes around cards. Corners are soft: controls `rounded-md` (10px), team and POW buttons `rounded-lg`, cards `rounded-xl`, bottom sheets `rounded-2xl`, badges and pills `rounded-full`. No colored left-border stripes for callouts or highlights; use a tinted fill or an icon.
- **Type, two levels:** Barlow Condensed capitals (`font-display`) for page and section titles (`h1`–`h3`), team names, scores and big stat numbers. Barlow, in sentence case, for everything else: buttons, badges, tabs, table headers, labels, small headings (`h4`, `Eyebrow`) and card titles. Both are bundled with `@fontsource`, so the app makes no font requests.
- **Copy:** say it once and briefly. Rules and footnotes go behind a disclosure (`<details>`, as "How locks work" on the pick sheet) or on How to play, not in paragraphs above the content. Times use `relativeTime` (`src/format.ts`).
- **Components:** add shadcn components with `pnpm dlx shadcn@latest add <name>` from `apps/web`, then run `pnpm format`. The generated files are ours to edit: `button`, `input` and `badge` are already retuned for touch (44px controls, 16px field text so iOS doesn't zoom). `Avatar` (`components/Avatar.tsx`) shows a player's initials; it is decorative, so show the name beside it.
- **Phone first.** Tap targets are at least 44px. Use a whole-row link rather than a word of link text. Anything pinned to the bottom edge uses `TAB_BAR_OFFSET` to sit above the tab bar. Wide tables take the `card-rows` class, which turns each row into a card below `md`; those tables carry explicit ARIA roles because browsers drop table semantics once the display changes. Tables that scroll sideways instead sit in a `rounded-xl bg-card` wrapper and take `sticky-first`, so the player column stays put; mark the signed-in player's row with `data-me`.
- **Matchup sheet:** each pick card has a "Stats, news & market" row that opens `MatchupSheet` (a bottom sheet) for that game, loaded on demand from `GET /api/games/:gameId/insights`. Everything in it is public background (ESPN, Kalshi), never this league's picks, so it doesn't touch the privacy rule. Either source can fail or change without notice: the endpoint returns `null` for that half and the sheet shows what arrived. Market prices are read against the league's own spread; no sportsbook branding or betting links.
- **Team logos** come from ESPN's image CDN through `TeamLogo` (`components/TeamLogo.tsx`), keyed by the team abbreviation and resized by ESPN. They are decorative: always show the team name or abbreviation beside one. The browser loads them from `a.espncdn.com`, which the Content-Security-Policy in `public/_headers` allows for images; any new external host must be added there.
- **Security headers.** `public/_headers` sends HSTS (six months, `www` only), a CSP (scripts from `'self'` only; images from `'self'`, `data:` and `a.espncdn.com`; connections to `'self'` and Supabase), `frame-ancestors 'none'`, nosniff and a referrer policy with every page; the API adds the same through `secureHeaders()` plus `Cache-Control: no-store`. Keep inline scripts and inline `style` attributes on static HTML out of `index.html`.
- **Installable.** `apps/web/public/manifest.json` and the `apple-*` tags in `index.html` let the app be added to a phone's home screen, where it opens without browser chrome. The icons are committed PNGs drawn by `scripts/icons.mjs`. The only service worker is the push-only `public/push-sw.js` (served `no-cache` via `_headers`); it caches nothing, so nothing works offline. Keep the manifest's `theme_color` equal to the page's `theme-color` meta tag (`scripts/manifest.test.mjs` checks it).
- Use `useConfirm` (`components/ConfirmDialog.tsx`) instead of `window.confirm`.
- **Secondary and destructive row actions** (member roles and removal, removing a game, pinning a thread) live in a "⋯" `DropdownMenu` on the row, named `Options for <name>`; each item keeps a full accessible name ("Remove Pat"). Keep the one main action of a screen as a visible button.
- **Loading:** show a placeholder from `components/Skeletons.tsx` shaped like the screen, never a bare "Loading…" line. Each is a `status` region named for what is loading. The exception is opening the app: `Splash` (`components/Splash.tsx`), the POW mark over the whole screen, covers the session, profile and the first load of Your leagues, greeting the player by name once it's known. Later visits to Your leagues use the list skeleton. A load that fails shows `LoadError` (`components/LoadError.tsx`) with **Try again**, never a dead end; a lost session signs the player out with "Your session ended".
- **Screen changes** cross-fade through the View Transitions API in `navigate` (`router.tsx`), skipped under reduced motion and where unsupported.
- **Feedback goes where the user is looking.** The outcome of an action is announced with `notifyDone` / `notifyError` (`src/notify.ts`), a banner pinned just above the save bar, never in a message at the top of a long page. The exceptions sit beside their button: the pick sheet's save bar, and validation inside a form. A button that starts a request is disabled and says what it is doing ("Saving…") until it finishes.
- **Unsaved work is guarded.** A screen with edits that haven't been saved calls `useUnsavedGuard`, which asks before in-app navigation and warns on reload or tab close.

- `playwright` — drive a browser against the running app.

## Ports and worktrees

Every git worktree runs its own isolated stack, so agents can work in parallel.

- `scripts/ports.mjs` gives the main checkout (and CI) slot 0, the default ports: web 5173, API 8787, Supabase 54320–54329. Each linked worktree gets the next free slot `n`: web `5173+n`, API `8787+n`, Supabase `54320+10n` onward, and its own Supabase project (`football-weekly-picks-<n>`) with a separate database.
- Slots are recorded in `picks-port-slots.json` inside the shared `.git` directory and freed when the worktree directory is gone. Force one with `PICKS_PORT_SLOT=<n>`. CI selects an available port group with `scripts/ci-ports.mjs` before starting Supabase.
- `pnpm env:local` writes the ports into `.env` (`PORT`, `WEB_PORT`); Vite, the API, and Playwright all read them from there. Run it after `pnpm db:start` in every new worktree.
- Before deleting a worktree, run `pnpm sb stop --no-backup` in it to remove its containers and database volume.
- The local stack runs only what the app uses: Postgres, Auth, the API gateway, Studio, and the test inbox (Mailpit). All local email, from Auth and from the API (under `pnpm dev` and `pnpm worker:dev`), lands in the test inbox; E2E tests read it through `e2e/tests/inbox.ts`. Realtime, Storage, Edge Functions, and Analytics are switched off in `supabase/config.toml`; set `enabled = true` there when a feature needs one.

## Database changes

1. Edit `packages/db/src/schema.ts`.
2. `pnpm db:generate --name <short_description>` writes SQL to `supabase/migrations/` and refreshes the schema diagram in `docs/schema.md`. Review the SQL.
3. `pnpm db:reset` rebuilds the local DB from migrations + seed.
4. Commit the schema change, the migration SQL, `supabase/migrations/meta/`, and `docs/schema.md`.

- For SQL Drizzle can't express (triggers, functions, grants): `pnpm db:migrate:custom --name <desc>`, then fill in the empty file.
- **Renames:** when a change could be either a rename or a drop + add, `drizzle-kit generate` asks interactively, and agents can't answer the prompt. Agents should not attempt a column or table rename on their own. Stop and ask the human to run `pnpm db:generate` in a terminal and pick "rename". (A hand-written custom migration doesn't help, because drizzle-kit diffs against its snapshot in `migrations/meta/`, not the live DB.)
- **Never edit a migration that has been merged to main.** Add a new one.
- Migrations deploy before the new code ships, so keep them backward-compatible (expand, then contract).
- CI fails if `schema.ts` changes without a matching migration, or if `docs/schema.md` is out of date.
- `docs/schema.md` (ER diagram + table reference) is generated by `packages/db/scripts/erd.mjs`; never edit it by hand. Its descriptions are the `/** ... */` comments above tables and columns in `schema.ts`, so document new tables and columns there. A comment-only change needs `pnpm db:erd`.

## Testing

| Layer     | Tool                                                               | Location                                               | Covers                                                                      |
| --------- | ------------------------------------------------------------------ | ------------------------------------------------------ | --------------------------------------------------------------------------- |
| Unit      | Vitest (Node)                                                      | `packages/*/src/**/*.test.ts`                          | Pure logic and Zod schemas                                                  |
| API       | Vitest + `app.request()`                                           | `apps/api/test/`                                       | Routes, auth, DB behavior. DB suites skip unless `DATABASE_URL` is set      |
| Component | Vitest browser mode (Playwright Chromium) + `vitest-browser-react` | `apps/web/src/**/*.test.tsx`                           | Single components given props. No network                                   |
| E2E       | Playwright Test (Chromium + mobile WebKit)                         | `e2e/tests/`                                           | Real user flows across web → API → Supabase                                 |
| Script    | Node test runner                                                   | `scripts/*.test.mjs`, `packages/db/scripts/*.test.mjs` | Deploy and database tooling, credential redaction, CI ports, the manifest   |
| Contract  | Vitest (Node, live network)                                        | `apps/api/test/contract/*.contract.ts`                 | ESPN's and Kalshi's real responses against the app's URLs, schemas, parsers |

**Workflow for agents. Follow this before saying a change is done:**

1. `pnpm check` must pass.
2. If the change touches UI, routes, auth, or the schema: run `pnpm test:e2e` with `pnpm db:start` running.
3. For UI changes, also check visually: with `pnpm dev` running, use the Playwright MCP tools to open the web URL from `pnpm ports`, step through the changed flow, and take a screenshot.
4. Add or update tests at the lowest layer that can catch the bug. E2E covers critical user journeys only.
5. If the change touches how ESPN or Kalshi is read (`nfl.ts`, `insights.ts`, `teamLogoUrl` or `TEAM_ABBRS` in `packages/shared`): run `pnpm test:contract`, and extend `apps/api/test/contract/` to cover any new field or convention the app relies on. The app reads both leniently so it stays up when a feed changes; the contract checks are what notice.
6. When a rule or a player-facing flow changes, update the places that describe it: the How to play page (`apps/web/src/pages/HowToPlayPage.tsx`), the README ("Walking through a week", "League rules"), "Domain rules" here, and the comments at the top of `supabase/seed.sql`.

Conventions:

- Query by role, label, or text (`getByRole("button", { name: "Eagles" })`), never by CSS class. Add `aria-label`s so elements are reachable this way.
- Keep components presentational (data and callbacks in via props) so they're testable without mocks. The containers in `src/pages/` (and `App.tsx` for the session and profile) do the fetching.
- E2E tests sign up a fresh user per test (the `signedIn` fixture), so they never share state. Tests delete only rows they created; never truncate.
- Time-dependent logic takes a `now` parameter, so tests pass a fixed date rather than mocking timers. In the API, read time from the `now` dep; in the web app, from `useNow()` or `now()` in `src/clock.ts`, never `new Date()`. That keeps the local `CLOCK_OVERRIDE` (README, "Simulating a different date and time") working.

## Conventions

- Every table gets `.enableRLS()` with no policies. The API connects as a privileged role; RLS stops clients holding the public publishable key from touching tables directly via Supabase's REST API. Don't add RLS policies unless clients are meant to query Supabase directly.
- Request and response shapes live in `packages/shared` (Zod). Validate input with `zValidator`.
- Auth: clients sign in with Supabase and send `Authorization: Bearer <access_token>`. `requireAuth` verifies it and sets `c.var.user`.
- Keep routes chained on the Hono instance, otherwise `ApiType` loses route types and the web client breaks.

## Credentials and logs

- Remote database connections require verified TLS. `packages/db/src/connection.ts` is the shared policy for the Node API and `check-db-url.mjs`; the public Supabase CA is bundled and scoped to Supabase database hosts. In production the Worker connects through Hyperdrive, which verifies the database with `--sslmode verify-full` and the same CA; the health check still confirms the database leg is encrypted. Never disable certificate verification to work around a trust failure.
- API logs use route templates, generated request IDs, fixed readable messages, known error codes, and safe source locations. Never print raw errors, SQL parameters, request bodies/headers, or raw URLs. Extend the safe diagnostic vocabulary in `apps/api/src/logging.ts` when adding a new operation.
- CLI wrappers redact credentials before printing. `supabase-env.mjs` intentionally exports local credentials to `.env` or `GITHUB_ENV`; do not pipe it into public logs. It registers Actions masks before subsequent steps run.
- E2E allows only local database and auth services. Traces and screenshots are disabled because they can capture credentials. Reports contain test outcomes and are retained for three days. Host/proxy access logs need their own URL privacy settings.

## Runtime (Cloudflare Workers)

- `src/worker.ts` builds the app once per isolate and opens a Hyperdrive connection per request (and per Cron Trigger run). Hyperdrive's query cache is off (it isn't cleared by writes, so access checks and reads after a save would go stale); keep it off. Routes keep using `deps.db`; a stand-in forwards it to the current request's connection (`AsyncLocalStorage`). Don't touch the database outside a request.
- Work that outlives the response (a new thread's emails and notifications) goes through the `background` dep, which the Worker hands to that request's `waitUntil` and finishes before closing its connection. A bare un-awaited promise is cancelled once the response is sent. `waitUntil` has a time limit, so the outbox claims rows in small batches; whatever is cut off is retried by the cron.
- In-memory caches (`cached` in `insights.ts`, the results throttle in `weeks.ts`) are per isolate and keep only settled values: a Worker request must not await a promise another request started. Don't share in-flight promises, sockets or streams across requests.
- Workers Paid ($5/month): 10 million API requests and 30 million CPU-ms a month included, unlimited Hyperdrive queries. Static asset requests are free. API requests use roughly 10–130 ms of CPU (waiting on I/O doesn't count); `limits.cpu_ms` in `wrangler.jsonc` caps each invocation at 2 s, so raise it before adding heavier work. Keep heavy computation out of hot routes; Workers Logs show CPU time per request. A Workers spend limit blocks `/api/*` (error 1103) and the cron at $10 of usage, so a request flood can take the app down. A zone rate limiting rule (dashboard only) blocks an IP for 10 s after 50 `/api/*` requests in 10 s, before the Worker runs; the busiest real player so far peaked at 20. It only covers the custom domain, so `wrangler.jsonc` keeps `workers_dev` and `preview_urls` off. Request bodies over 64 KB get a 413.
- `CLOCK_OVERRIDE` is Node-only. The Worker reads only `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `OPERATOR_USER_IDS`, `UNSUBSCRIBE_SECRET` and the three `VAPID_*` keys (secrets), `APP_URL` and `NODE_ENV` (`production` in `wrangler.jsonc`; `pnpm worker:dev` sets `development`, which drops the TLS requirement for local Postgres and lets `INBOX_URL` send email to the test inbox), and optionally `EMAIL_FROM`, `EMAIL_DAILY_LIMIT` and `EMAIL_MONTHLY_LIMIT`.
- Email Sending to players is why the account is on Workers Paid (the free plan sends only to verified addresses).

## Deploy (GitHub Actions → Cloudflare)

- `ci.yml` runs on PRs. Job `check`: Gitleaks history scan with redacted output, lint, typecheck (including the Worker against its runtime types), migration drift check, unit + component/script tests, web build + Worker bundle. Job `e2e`: local Supabase, DB-backed API tests, Playwright against the Worker (`E2E_TARGET=worker`; report uploaded as an artifact).
- `uptime.yml` checks `$APP_URL/api/health` every 15 minutes and opens one `uptime` issue per outage, closing it on recovery. Cloudflare Notifications cover Worker errors, DDoS and certificates; Dependabot (`.github/dependabot.yml`) opens update PRs. README, "Monitoring and recovery", has the runbook (rollback doesn't undo migrations; the Free Supabase plan keeps no backups).
- `contract.yml` runs `pnpm test:contract` daily (and on PRs touching the ESPN or Kalshi parsing). A failed scheduled run opens an issue labeled `feed-contract`, or comments on the open one; the next passing run closes it.
- `deploy.yml` runs on push to main: CI → connection-string check → `supabase db push` → `pnpm build` → `wrangler deploy` → `scripts/check-live.mjs` (polls `$APP_URL/api/health`). The web build and API go live together, but open tabs keep the old web build, so the API must stay backward-compatible with it. A failed live check doesn't undo the deploy; `wrangler rollback` does.
- `apps/api/wrangler.jsonc` defines the Worker `pow-pickem`: assets from `apps/web/dist` with SPA fallback, `run_worker_first` for `/api/*`, the `HYPERDRIVE` binding, the `EMAIL` (`send_email`) binding limited to `noreply@pow-pickem.com`, the Cron Trigger (`*/5 * * * *`), placement in `aws:us-east-1` (the Supabase region), logs and traces on. `apps/web/public/_headers` caches `/assets/*` as immutable.
- Secrets (GitHub environment `production`): `SUPABASE_DB_URL` (session pooler URL for migrations; GitHub runners are IPv4-only), `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`; variable `APP_URL`. Worker secrets (`wrangler secret put`): `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, optional `OPERATOR_USER_IDS`, `UNSUBSCRIBE_SECRET` to turn email on, and `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` to turn push on (README, "Push notifications"). Email setup (Workers Paid, domain onboarding, Supabase SMTP and templates) is in the README under "Email".
- The web build needs no env vars (it fetches `/api/config` at runtime). Supabase Auth's Site URL and redirect URLs must point at the public URL.
- Only `wrangler.jsonc`, `src/worker.ts` and the deploy job are Cloudflare-specific; `src/index.ts` still runs the API on any Node host with `PORT` and `DATABASE_URL`.
